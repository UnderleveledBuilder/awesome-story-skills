**What it solves**: The model can't remember the settings it made up. Later in the book, system rules contradict each other, character and place names drift, and settings that were already written get reinvented by the model, wrongly. Putting every setting in the prompt doesn't fit either. Worldbuilding methods keep settings outside the model and retrieve them when needed; where state has to be strict, it is handed over to a program entirely.

**Common designs**

1. **Keyword-triggered lorebooks (world info)**: settings are split into entries, each with trigger words. An entry is inserted into the context only when one of its trigger words appears in recent dialogue or prose. This is core infrastructure for roleplay frontends, and many later tools can import its format. Examples: [SillyTavern](https://github.com/SillyTavern/SillyTavern), [KoboldAI-Client](https://github.com/KoboldAI/KoboldAI-Client), [Risuai](https://github.com/kwaroran/Risuai), [Writingway](https://github.com/a-omukai/Writingway) (setting bible injected on mention)
2. **A structured entity store, retrieved per scene**: characters, locations, factions, and systems are each stored as files or cards with fields, and they reference each other. When writing a passage, retrieve the entries that match its point on the timeline, its location, and the characters present. Examples: [AIStoryBuilders](https://github.com/AIStoryBuilders/AIStoryBuilders), [worldbuilder](https://github.com/gofastercloud/worldbuilder) (11 entity types cross-referenced in Markdown+YAML, with graph validation of two-way relationships and timelines), [NovelForge](https://github.com/RhythmicWave/NovelForge), [vibe-writing](https://github.com/pakholeung37/vibe-writing) (a wiki with two-way links; red links mark settings still to be filled in)
3. **Extracting settings back out of the prose**: after each chapter, have the model extract new characters, locations, relationships, and rule changes, write them back to the setting bible or a knowledge graph, and retrieve them for the next chapter. Examples: [novelwriter](https://github.com/Hurricane0698/novelwriter), [lore-weave](https://github.com/letuhao/lore-weave), [AIxiezuo](https://github.com/yefeng2renxing/AIxiezuo) (the protagonist's cultivation level, items, and relationships stored as per-chapter state JSON), [novel-smith](https://github.com/huanweide/novel-smith)
4. **The engine owns state; the model only proposes**: hard facts such as numbers, items, locations, and character identities are held by code. The model outputs commands or state patches, which take effect only after the engine validates them, and the authoritative state is injected into the prompt every turn. Most common in interactive fiction and tabletop RPGs. Examples: [ai-novel-studio](https://github.com/weike-zhang/ai-novel-studio) (a patch that renames a character is rejected), [StatefulLore](https://github.com/cgstever/StatefulLore), [yumina-oss](https://github.com/lovetimo0421/yumina-oss), [faramita-worlds](https://github.com/Nobeta-Work/faramita-worlds) (field-level deltas and conflict detection)
5. **Set the rules first, then expand**: work out consequences from a few core settings instead of writing an encyclopedia first. Examples: [worldbuilding-skill](https://github.com/tahini2007/worldbuilding-skill) (no more than 3 core deviations, each pushed through a seven-level chain of consequences, then a review of narrative interfaces and the "mystery budget"), [DUNGEON_ARCHITECT](https://github.com/gloria-yin/DUNGEON_ARCHITECT) (designs a dungeon's surface and its hidden truth separately, plants twists in advance, then injects them into the lorebook), [Narraverse-Engine](https://github.com/wssyh339/Narraverse-Engine) (several agents deliberate turn by turn to work out world rules, which are stored after human confirmation)

**Trade-offs and pitfalls**

- **Keyword matching misses entries at scale.** The README of [sillytavern-DeepLore](https://github.com/pixelnull/sillytavern-DeepLore) says lorebooks start to fail at around 80–100 entries: if the scene is about the consequences of breaking an oath and nobody types the entry's name, the entry doesn't trigger, and the model makes something up instead. It switched to keywords plus BM25 for a rough filter, then has the model read entry summaries to make the final pick, then gates by era, location, and character. The cost is one extra model call per turn.
- **More settings means a more crowded context.** Injection needs a budget. faramita-worlds gives each lorebook card activation rules, an injection position, and a budget. [bragi](https://github.com/wailers9/bragi) keeps full text only for the current time-and-place node and summaries for nearby nodes. [WenShape](https://github.com/unitagain/WenShape) decays facts by chapter distance.
- **Automatic extraction writes mistakes into canon.** novelwriter treats extraction results as drafts that enter the store only after the author reviews them. [Aventuras](https://github.com/AventurasTeam/Aventuras) uses a separate agent to merge duplicate entries and fill gaps. Without review, a misreading becomes the basis for everything written after it.
- **Settings change over time.** If you store only one current state, memories and flashbacks easily break continuity. AIStoryBuilders splits character and location descriptions into timeline segments and retrieves the version for the segment being written.
- **You don't need to build the encyclopedia first.** worldbuilding-skill caps core deviations at 3. vibe-writing leaves undecided settings empty as red links and fills them in when the writing gets there.

**Where to start**: [novelwriter](https://github.com/Hurricane0698/novelwriter) suits writing long novels or continuing an existing work; the full chain is there: extracting settings from prose, author review, injection per chapter. [SillyTavern](https://github.com/SillyTavern/SillyTavern) suits roleplay or interactive stories; learn its lorebook first, since many similar tools can import that format. [worldbuilding-skill](https://github.com/tahini2007/worldbuilding-skill) suits designing a solid world before you start writing, and it can also diagnose why existing settings get harder to wrap up the more you write.
