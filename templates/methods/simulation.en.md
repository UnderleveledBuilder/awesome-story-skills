**What it solves**: When one model plays the author and every character at once, characters learn secrets too early and suddenly act stupid to push the plot along. Side characters appear only when needed and stop existing once they leave the scene, so the world feels like a painted backdrop. Character simulation splits "writing" into "act first, write after": each character decides on its own, the world state is resolved separately, and only at the end is it turned into prose.

**Common designs**

1. **Characters act first, a director writes**: one agent per character, with its own persona, memory, and beliefs. Each first proposes its own action or scene strategy; a director or narrator merges the separate POV lines into a chapter spec, which goes to a writer to turn into prose. novel-studio lets important characters make decisions within a window of up to 3 chapters, and the world arbiter only rules on consequences; it cannot change what characters intend. Examples: [hermes-novel-generator](https://github.com/rwcrosk-arch/hermes-novel-generator), [fictionforge](https://github.com/wanqili857-byte/fictionforge), [novel-studio](https://github.com/Xiaoyangy/novel-studio), [CoDi](https://github.com/Speeditidious/CoDi)
2. **A bottom-up world sandbox**: following the Generative Agents approach, characters act on their own, either through "perceive → plan → act → reflect" or tick by tick. The system only records events, and the story is pulled out of the timeline afterward. Common in fan-fiction simulations of well-known works (Dream of the Red Chamber, Westworld). Examples: [OpenStory](https://github.com/ZJU-LLMs/OpenStory), [StoryBox](https://github.com/amcghm/StoryBox), [clawloom](https://github.com/Aaron-ou/clawloom), [taleweave-ai](https://github.com/ssube/taleweave-ai)
3. **Information isolation**: objective facts, each character's perceptions, memories, and narration are stored in separate layers, and each stage calls the model separately. A character gets only the information it could reasonably see, and the narrator writes only what the player can see. In gamentic, characters cannot change the world directly; they can only make claims to the narrator, who rules on them that turn. Examples: [Sonder_Engine](https://github.com/N0819/Sonder_Engine), [project-lunar](https://github.com/horizonfps/project-lunar), [gamentic](https://github.com/hec-ovi/gamentic), [ai-murder-mystery](https://github.com/ScottishFold007/ai-murder-mystery)
4. **Resolve state first, narrate after**: the world state is the single source of truth. Character and player actions are first turned into state changes and resolved by rules, then the model writes the result as prose. payador first has the model predict how the player's input changes the world state, then writes the narration from the new state. world-walker specifies that the Agent only turns the JSON output by the engine into text and must not make up numbers. Examples: [payador](https://github.com/pln-fing-udelar/payador), [world-walker](https://github.com/badhope/world-walker), [WorldForge](https://github.com/EidzokuxS/WorldForge), [AaaliceTavern](https://github.com/WalkingMeatAxolotl/AaaliceTavern)
5. **Local simulation before writing**: instead of running the whole world, have characters act out a few rounds, or explore several paths, only before key scenes; then pick a plausible direction and write it. Examples: [creative-writing-skills](https://github.com/haowjy/creative-writing-skills) (a character-simulation subagent in the planning stage), [AnySpark](https://github.com/Mikexujunrui/AnySpark) (many cheap explorations, then a judge picks the best), [novel-distiller](https://github.com/FutureFuzzy/novel-distiller) (first distills a thinking SKILL.md for each character, then simulates), [open-skoob](https://github.com/OmMaBaMiHong/open-skoob)

**Trade-offs and pitfalls**

- Pure emergence tends to sprawl. A sandbox with no goal goes in circles, so projects often add a layer of top-down constraints: ScrollWeaver uses event chains to steer the overall direction; nest-drama sets must-reach plot nodes and flexible ones, and requires that they be reached through cause and effect inside the world; StoryBox passes the simulation results to a narrative planner that organizes them into a long novel.
- Cost rises with the number of characters. WorldForge considers running full decision-making for every character every turn slow, noisy, and expensive, so it splits NPCs into three tiers (key, regular, temporary) and only key NPCs make full decisions. novel-studio activates characters by event and limits the context at each stage.
- Rules that are locked down too tightly hurt the narrative. When glyphkeeper stopped being updated, its author's own assessment was that the multi-Agent pipeline with event sourcing and physics arbitration "over-constrained the LLM's narrative flexibility", and latency was high too. WorldForge's compromise is to give the narrator a small description budget that allows only harmless surface details.
- Isolation has to be built into how the context is structured. Sonder_Engine rules that truth, perception, memory, belief, and narration must never be merged into the same context. ai-murder-mystery adds a critique-and-revise step after a character replies, specifically to stop secrets from leaking.
- A record of the performance is not a novel. Turn-by-turn records read like a plain log of events and need more work: fictionforge marks where the twists land when it builds the chapter spec, and in CoDi an editor rewrites them into script or novel format.

**Where to start**: [hermes-novel-generator](https://github.com/rwcrosk-arch/hermes-novel-generator) is good for understanding the flow first: one SKILL.md plus five agent prompts. Characters produce strategies without seeing each other, the narrator weaves them into prose, and the characters then check that their voices are right. [novel-studio](https://github.com/Xiaoyangy/novel-studio) is a full long-novel project built on the same idea, with windowed simulation, arbitration, and ledgers. [Sonder_Engine](https://github.com/N0819/Sonder_Engine) suits developers building interactive fiction: director, perception, character, narration, and commit are separate steps, and each one can be rerolled or edited by hand.
