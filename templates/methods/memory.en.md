**What it solves**: The whole book doesn't fit in the context, and the model doesn't keep track of anything on its own. A few dozen chapters in, dead characters show up again, foreshadowing gets planted but never paid off, and characters know about things that haven't happened yet. This method hands "remembering" over to files, databases, and retrieval instead of relying on the model's recall.

**Common designs**

1. **Keyword-triggered setting entries**: each character, location, or rule gets a few trigger words, and the entry is injected into the context when one of them appears in recent text. KoboldAI's World Info and SillyTavern's lorebook both work this way; Auto-Cards also recognizes named entities in the story and writes them up as new cards automatically. Most common in interactive fiction and roleplay. Examples: [KoboldAI-Client](https://github.com/KoboldAI/KoboldAI-Client), [SillyTavern](https://github.com/SillyTavern/SillyTavern), [Writingway](https://github.com/a-omukai/Writingway), [Auto-Cards](https://github.com/LewdLeah/Auto-Cards)
2. **Recent text in full, older text as summaries**: the most recent content is kept as the original text, and earlier content is compressed into summaries level by level. otaku always sends the first 20 and the last 150 entries in full to preserve the style, and replaces the middle with scene summaries. word-compiler splits the context into three rings (project, chapter, scene), compresses by priority when it goes over budget, and gives the scene ring at least 60%. Examples: [RecurrentGPT](https://github.com/aiwaves-cn/RecurrentGPT), [otaku](https://github.com/enclavum/otaku), [NovelFlow](https://github.com/DongxUETAFFY/NovelFlow), [word-compiler](https://github.com/2389-research/word-compiler)
3. **A state ledger, settled after writing**: character states, foreshadowing, and the timeline are stored as structured files or in a database. After each chapter, the model submits changes, and they are written to disk only after a program validates them. tianming-novel-ai-writer requires the prose to come with a JSON change declaration, which is committed only after passing six gates. ai-novel-studio accepts only state patches, which the server validates and commits as a transaction; the model cannot change the name of a character who has already appeared. Examples: [inkos](https://github.com/Narcooo/inkos), [tianming-novel-ai-writer](https://github.com/zy-zmc/tianming-novel-ai-writer), [agent-novel](https://github.com/RTY798/agent-novel), [ai-novel-studio](https://github.com/weike-zhang/ai-novel-studio)
4. **Retrieval: keywords, vectors, and graphs**: index facts, summaries, and the original text, and before writing, pull the fragments relevant to the current chapter. WenShape picks facts with BM25 plus entity boosting, then decays their weight by distance from the current chapter. saga tracks characters, events, and relationships in a Neo4j knowledge graph, and DOME uses a knowledge graph during writing to detect and resolve contradictions. Examples: [WenShape](https://github.com/unitagain/WenShape), [saga](https://github.com/Lanerra/saga), [DOME](https://github.com/Qianyue-Wang/Generating-Long-form-Story-Using-Dynamic-Hierarchical-Outlining-with-Memory-Enhancement), [Ai-Novel](https://github.com/inliver233/Ai-Novel)
5. **Separate records by time and point of view**: the same fact can be true in one chapter and false in another, and characters, the author, and readers each know different things. neuro-book does event sourcing with timeline slices, and the world state at any moment is computed from the slices before it. jarvis-write binds each fact to the range of chapters in which it holds. oh-story-claudecode and Closure record the author's truth separately from what readers already know, and Smart-Memory records separately what each character knows. Examples: [neuro-book](https://github.com/notnotype/neuro-book), [jarvis-write](https://github.com/ynnyh/jarvis-write), [oh-story-claudecode](https://github.com/zenstory-ai/oh-story-claudecode), [Closure](https://github.com/AoharuCat/Closure), [Smart-Memory](https://github.com/senjinthedragon/Smart-Memory)

**Trade-offs and pitfalls**

- **Keyword triggering has a scale limit**: DeepLore's README says lorebook keyword matching starts to fail at around 80–100 entries; if the prose doesn't contain the word, the relevant entry doesn't trigger. It added a step where the model reads entry summaries to make a finer selection, at the cost of one extra call per turn.
- **Write-back needs a gate**: automatic extraction writes mistakes into canon. In Story-Editor the editor model only proposes, and changes enter the ledger only after the author approves them. novel-agent-studio extracts memory only from prose the author has accepted. Novel-factory requires ledger entries to cite the prose, and entries that don't match are not recorded.
- **Memory needs a budget and an authoritative source**: oh-story-claudecode caps its state card at 12 KiB, and the main session passes only the parts relevant to the current chapter to the writer. ProseForge sets a budget for each seat at 65% of the real context window. inkos treats the raw files as authoritative, so the retrieval index can be rebuilt.
- **Constraints that are too rigid hurt the narrative**: when glyphkeeper stopped being updated, its author explained that event sourcing plus physics arbitration "over-constrained the LLM's narrative flexibility" and also slowed down responses. agent-novel blocks strictly only on factual errors and treats style rules as observations only.
- **The benefit varies by model**: in the first round of results from fictionforge's CanonBench, the two models with more violations when writing without injected context improved clearly once context was injected, while the model with the fewest violations barely changed. The author also issued one correction: most of one "model difference" came from judge false positives and truncated chapters. Test with your own model before going live.

**Where to start**:

- [oh-story-claudecode](https://github.com/zenstory-ai/oh-story-claudecode): suits authors writing web novels with a coding agent. Memory is just files in the project, and the demo has a real state card from a continuation to compare against.
- [RecurrentGPT](https://github.com/aiwaves-cn/RecurrentGPT): suits developers who want to understand the minimal "short-term memory + long-term memory" structure. There is little code, and it comes with a paper.
- [sillytavern-DeepLore](https://github.com/pixelnull/sillytavern-DeepLore): suits people already using SillyTavern lorebooks who have so many entries that keywords are no longer enough.
